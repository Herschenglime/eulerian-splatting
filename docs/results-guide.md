# Eulerian Splatting results: `<name>`

One training run of *Eulerian Gaussian Splatting using Hashed Probability Pyramids* (Polansky et al., CVPR 2026) on one of our captures, trained on a HiPerGator B200 for the EEL5406 final project. The method starts from samples spread uniformly through space and learns a probability distribution over where Gaussians should be, instead of growing them from a COLMAP point cloud.

The folder mirrors the repo (github.com/Herschenglime/eulerian-splatting): extract it into a clone and the commands below work as written. This file is generated by `scripts/pull_results.py` from `docs/results-guide.md`; this run's numbers are at the bottom.

## What each file is

### The splat
| File | What it is |
|---|---|
| `output/<name>/<run>/<name>.ply` | **The final splat, ready for viewers** (SuperSplat, any standard 3DGS viewer). Standard 3DGS PLY: position, colour as spherical harmonics up to degree 3 (view-dependent colour), logit opacity, log scale, rotation. Rotated upright (scene up = −y, what viewers expect). Nothing is cropped. |
| `output/<name>/<run>/*_light*.ply` | If present: a smaller copy for viewing (base colour only, far background and near-invisible Gaussians removed). |
| `output/<name>/<run>/point_cloud/iteration_*.ply` | **Raw training output, not for viewers.** Opacity is stored activated (0–1) and scales in world units, so a viewer shows huge transparent blobs; the frame is the training frame (up = −z). These are what `render.py` loads. The two iterations are the two phases (below). |

**Large files in SuperSplat:** a 15M-Gaussian splat is 3–4 GB, which a browser may struggle with. Gaussians far outside the scene (sky, distant background) also make SuperSplat open zoomed out and limit how close you can get. To cut both, keep only Gaussians within radius 1000 (needs `numpy` and `plyfile`):
```bash
python scripts/crop_ply.py output/<name>/<run>/<name>.ply cropped.ply --max_radius 1000
```
A smaller radius (~10) drops distant background too. `scripts/export_ply.py` on a `point_cloud/` PLY can also drop the view-dependent colour (`--sh_degree 0`, ~4x smaller) or faint Gaussians (`--min_opacity 0.005`); it needs PyTorch.

## How to read the results

- **Held-out views:** with `holdout: true`, every 8th image (by filename) was never used for training. Renders of those cameras are an honest test; renders of training cameras always look better.
- **Two phases:** the first 60,000 iterations are the *probabilistic* phase: each iteration draws ~15M Gaussian centers from the learned distribution, so Gaussians "flow" toward surfaces. The last 5,000 are *refinement*: one final sample is frozen into ordinary 3DGS Gaussians and fine-tuned (positions fixed). `iteration_60000.ply` is before refinement, `iteration_65000.ply` (and `<name>.ply`) after.
- **The timelapse:** early frames are fog, because samples start uniform over the whole volume. The centers images show the dots condensing onto surfaces; background condenses last and stays coarser.
- **PSNR** (higher is better, in dB): ~20 is recognisable but soft, ~25 sharp, 30+ hard to tell from the photo. The PSNR in the `test_visualization` file names comes from a single random sample, so it moves by a few tenths between evaluations. The paper reports ~27–29 dB on curated benchmark scenes; ours are handheld phone captures with fewer views. **SSIM** (0–1, higher is better) measures structure; **LPIPS** (0–1, lower is better) is a learned perceptual distance.
- **Background is coarse by design:** space outside the box around the training cameras is compressed into an outer shell, so the sky and distant buildings get few, large Gaussians and look painterly.
- **Artifacts we have seen so far:** needle-like streaks on flat surfaces after refinement; smeared fine texture (lettering, shell pattern); faint ghosts where people walked through some photos; colour shifts where the phone's auto exposure changed between photos.

## Reproduce scores and per-view renders

Needs this repo's full environment (`uv sync`, which needs an NVIDIA GPU and a CUDA 12.8 `nvcc`; see the README) and a GPU with ~12 GB (8 GB untested). Extract this folder into the repo root so `output/` and `data/` line up, then:
```bash
uv run python render.py  --config=capture --source_path=data/<name> --model_path=output/<name>/<run> --skip_train
uv run python render.py  --config=capture --source_path=data/<name> --model_path=output/<name>/<run> --skip_train --eval_iteration=60000
uv run python metrics.py --model_paths output/<name>/<run>
```
The first renders the final splat, the second the pre-refinement sample. The paths on the command line override the HiPerGator paths saved in `cfg_args`. Output: `renders/test/ours_<iter>/{renders,gt}/` and `results.json` / `per_view.json` (PSNR, SSIM, LPIPS). `metrics.py` downloads the LPIPS weights the first time.
